# Security policy

## Supported version

Security fixes are applied to the latest version on the default branch.

## Report a vulnerability privately

Do not open a public issue for a suspected vulnerability, exposed credential, or sensitive-data leak.

Use GitHub's private vulnerability reporting from the repository **Security** tab. Include:

- the affected file or behavior;
- reproduction steps;
- potential impact;
- a suggested mitigation, if known.

Do not include real customer data or active credentials in the report. Replace sensitive values with safe markers.

## Scope

Relevant reports include unsafe file writes, unexpected transcript persistence or transmission, installer path traversal, dependency or workflow compromise, and accidental inclusion of credentials or confidential data.
